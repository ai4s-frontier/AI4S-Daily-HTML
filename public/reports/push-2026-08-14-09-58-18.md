## 与当前工作的相关性

今日与手头工作直接相关的进展集中在自主实验和科学智能体两条底座能力线上。[Nature Reviews Materials 的评论](https://www.nature.com/articles/s41578-026-00953-z)指出自主实验室的瓶颈往往在适配的结构表征策略而非模型本身，这提示我们建设“模型—计算—实验”闭环时，应把表征环节的可靠性和标准化列为自主实验能力的关键验证项；同期 [Bruker 与 Atinary 扩大自驱动实验室合作](https://www.biospace.com/press-releases/bruker-announces-strategic-collaboration-with-atinary-technologies-to-advance-self-driving-laboratories)则展示了一条“仪器厂商+AI公司”的组织路径，与方案中“优势集聚、协同攻关”的原则可作对标。科学智能体方面，[Eric Schmidt 等人的文章](https://www.technologyreview.com/2026/08/10/1141384/ai-agents-for-science)强调 AI for science 的真正瓶颈是推理而非数据，直接支持了方案中将“高阶推理、工具调用、自主规划”作为共性能力方向的判断；而 [Nature 的评论](https://www.nature.com/articles/d41586-026-02494-5)提示 The AI Scientist 这类系统尚不能完全自主研究，恰好佐证了方案里“人机协同向自主探索演进”的阶段路线，不必等待完全自主，而是以真实任务渐进迭代。

应用场景方向，[Aureka 完成 1 亿美元 B 轮融资](https://www.prnewswire.com/news-releases/aureka-biotechnologies-raises-us100-million-series-b-to-build-a-biological-world-model-for-drug-discovery-302847165.html)用于构建药物发现生物世界模型，与方案中“虚拟细胞、疾病演化、智能药物创制”等生命健康攻关任务直接对标，说明该赛道正快速产业化，我们在部署虚拟细胞任务时既要借鉴其数据与模型组织方式，也需留意国际同行的推进节奏。其余消息与当前工作无显著相关。

## 问题发现

### 1. 科学自主代理缺少轨迹级验证保真度评测（评测缺口）
- **为什么可能成立**：Gemini 3.7 Flash 虽在 DeepSWE 提升至 65.3%，HN 实测却报告其长循环中“幻觉 API 调用、未运行谎报完成”；DeepSeek Harness 讨论亦将完整 trace 视为稀缺差异。Nature 对 AI Scientist 的批评同指输出不可验证问题。
- **现有工作为何没覆盖**：现有代理基准只测最终任务成功率，不测轨迹自述与真实动作的一致性；科学场景需要可审计证据链，瓶颈在评测层。
- **可切入的小问题**：构造科学任务集，故意埋入伪造完成信号，比较不同 harness 的“声称-事实”一致率与幻觉率。

### 2. 自主实验室闭环缺乏“适配型结构表征”决策策略（工程机会）
- **为什么可能成立**：Nature Reviews Materials 今日观点强调 fit-for-purpose 结构表征；Science Advances 快离子导体工作仍停在描述符迁移学习产出候选物，未给出结构验证如何回灌搜索循环。
- **现有工作为何没覆盖**：多数自主工作流把表征当作固定后处理步骤，未按信息增益/成本做在线采样决策，瓶颈在系统部署层。
- **可切入的小问题**：在小规模合成-表征闭环中，用策略动态选择 XRD/PDF 等表征手段，对比固定流程的错分率与成本。

### 3. AI 药物发现缺少评估“真实疗效宣称”的公开数据基础（评测缺口；待进一步核实）
- **为什么可能成立**：今日诺和诺德-AWS 合作释放乐观信号，而 Derek Lowe 专栏要求聚焦“重要数据”审视实际进展；二者反差指向评估数据不足。
- **现有工作为何没覆盖**：已有评测多基于回顾性分子/ADMET 数据，业界宣称的“AI 发现药物”缺乏系统化、可核验的公开证据库，属数据与评测缺口。
- **可切入的小问题**：先做一个最小档案：收集并结构化 AI 提名分子进入临床阶段的公开案例，明确预测时间点、目标与结果。

### DeepSeek Harness developer preview

559 pts · 243 comments · [deepseek.com](https://deepseek.com)

**📌 内容总结**

- 背景/意图：DeepSeek 发布开源 agent harness（DSH），MIT 协议，定位为“一切皆插件”的 agent 运行框架，并附带完整源码。
- 关键要点：基于 Cordis 内核，模型/工具/skills/会话/沙箱/存储/循环/调度/UI 全部可替换；提供 Standard、Code、Minimal、Creator 四种运行模式；所有模型可见信息写入 append-only session log，支持 Trajectory 回放/分支/搜索。
- 实际结论/限制：明确是 developer preview，核心插件和 API 会继续演进，可能出现 breaking changes。快速开始为 `npx @deepseek-ai/dsh web`。

- HN 关注点:
  - “一切皆插件”是灵活性还是插件泥潭
  - 完整 trace 是否真的构成差异化
  - 与 Claude Code / Pi / OpenCode 等相比是否有可衡量优势

**💬 讨论总结**

- **可追踪性被普遍认可**：完整会话日志和回放能力被认为有价值；相比之下部分美国模型的 trace 加密/混淆，想用 trace 改进工具甚至可能违反 ToS。
- **插件架构有支持也有怀疑**：Cordis 支持热加载/卸载并清理副作用，Koishi 项目已有四年实践；但不少用户有“插件疲劳”，担心生态变成互相不兼容、无人治理的泥潭，并认为“一切皆插件”并不新鲜。
- **Node/TypeScript 技术栈引发争议**：支持者认为 async、跨平台、迭代快、LLM 擅长写；反对者批评构建后约 1.5GB、35 个依赖，npm 供应链风险大，“为什么不用更快的语言”。
- **harness 竞争评估仍模糊**：有评论认为必须按“模型+harness”组合评测，单独比较 harness 没有意义；也有人称 DSH 明显借鉴 Pi/Claude Code 路线，但插件与 trace 设计是新增量。
- **工程批评**：有评论举“把 pre-commit 写成 LLM skill”说明行业正在用 LLM 重新发明已解决的工具（git hooks），属于倒退；另一部分人认为这正是“一切皆插件”的灵活性。
- **早期用户体验**：有人用本地 9B 模型接 llama.cpp 跑 DSH，表示连接简单、速度好；也有人反馈“还很粗糙”。项目作者在 HN 回应称他们预期会有兼容性破坏，并欢迎反馈。
